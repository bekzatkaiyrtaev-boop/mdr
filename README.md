# МДР — скелет (v0)

Инструмент для совместного ведения сводного реестра проектной документации:
иерархия проект → позиции (здания) → листы (документы) → хронология
согласований, с правами по разделам (каждый проектировщик — только свой
раздел).

Это первая рабочая версия («скелет») — статика без сборки, база данных и
авторизация через Supabase (бесплатный тариф).

## Запуск с нуля

1. **Создать проект на [supabase.com](https://supabase.com)** (бесплатно).
2. В `SQL Editor` выполнить целиком файл [schema.sql](schema.sql) — создаст
   все таблицы, права доступа (RLS) и триггеры.
3. `Settings → API` — скопировать `Project URL` и `anon public` ключ, вставить
   их в [config.js](config.js) вместо заглушек.
4. `Authentication → Providers → Email` — убедиться, что вход по
   email/паролю включён (по умолчанию включён). Для тестового пилота можно
   отключить подтверждение почты (`Authentication → Settings → Email Auth →
   Confirm email` → выключить), чтобы не настраивать SMTP.
5. Открыть [index.html](index.html) — зарегистрировать первого пользователя
   (это будете вы). Первый зарегистрированный автоматически получает роль
   «ГИП» — ручные правки в Table Editor не нужны. Всем следующим
   пользователям роль назначаете уже вы через вкладку «Пользователи» в
   самом приложении.
6. Разложить папку как статический сайт (Vercel free tier, или просто
   открыть `index.html` локально/раздать по сети — Supabase работает из
   браузера напрямую, отдельный сервер не нужен).

## Что уже есть

- Роли: ГИП и Помощник ГИПа — полный доступ (шапка проекта, разделы и
  исполнители, управление пользователями, дерево позиций/зданий), Инженер —
  листы в своём разделе.
- Права проверяются на уровне базы данных (RLS), а не только в интерфейсе —
  подделать запрос через консоль браузера нельзя.
- Автогенерация обозначения листа из номера договора + кода объекта + кода
  раздела + типа документа + номера + ревизии.
- Хронология согласований по каждому листу (клик по строке → модалка,
  добавление записей: направлено / замечания / исправлено / согласовано /
  замечания стройплощадки).
- Сводная таблица с фильтрами (позиция / раздел / статус) и переключателем
  RU/EN.
- Отчёт: % готовности, разбивка по позициям и по разделам.

## Что сознательно упрощено (следующие шаги)

- Обозначение генерируется по одной фиксированной схеме — реальный формат
  вашей компании наверняка отличается для разных типов строк (тома,
  альбомы, изыскания) — нужно будет донастроить под реальные примеры.
- Нет импорта существующего Excel-файла (перенос истории вручную либо
  отдельным скриптом позже).
- Нет кнопки «Выгрузить в Excel» (важно добавить до полного перехода —
  см. договорённость о поэтапном переходе без риска потери данных).
- Нет ручной привязки комментария/источника изменения к письмам вне
  хронологии согласований.
- Список разделов (АС, КЖ, ES...) не валидируется — вводится как текст по
  договорённости внутри команды.
- Дерево позиций отображается плоским списком с отступами, без
  сворачивания/перетаскивания.

Дальше — тестируем на пилотном разделе, смотрим что мешает и донастраиваем.
