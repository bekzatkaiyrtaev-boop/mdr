# Раздача «Печати по слоям» и активация

Вкладка **«Материалы»** на сайте МДР: описание, кнопка «Скачать приложение», выдача ключа активации.
Видна всем, кроме «Наблюдателей»; реально работает только для тех, кто есть в списке «Пользователи»
(проверка — в базе, функция `can_use_materials()` из `migration_040_materials.sql`).

## Как это устроено

1. Файл программы (ZIP) лежит в **приватном** бакете Supabase Storage `materials`. Скачивание — по подписанной
   ссылке на 2 минуты; выдаёт её база только тем, кто проходит `can_use_materials()`.
2. Пользователь запускает программу → она показывает **код компьютера** `XXXX-XXXX-XXXX-XXXX`.
3. Пользователь вставляет код на сайте → Edge Function `issue-activation` проверяет его вход и членство в списке,
   подписывает строку `layerprint|<код>|<email>|<дата>` приватным ключом и возвращает **ключ активации**.
4. Пользователь вставляет ключ в программу → `LayerPrintActivation.cs` проверяет подпись зашитым **публичным**
   ключом и совпадение кода компьютера. Ключ бессрочный, привязан к компьютеру.

Один сотрудник может активировать **до 3 компьютеров** (`MAX_MACHINES_PER_USER` в `handler.js`). Лишнее место
освобождает ГИП: «Материалы → Все активации → Удалить». Повторный запрос с того же компьютера возвращает тот же ключ.

## Что нужно сделать один раз (в облаке — только по вашей команде)

```bash
# 1. ключи УЖЕ созданы локально (activation-private.pem — секрет, в .gitignore, сохраните в менеджере паролей).
#    Не перегенерируйте: публичный ключ уже зашит в сборку 1.3.

# 2. секрет и функция в Supabase
supabase secrets set ACTIVATION_PRIVATE_KEY="$(cat activation-private.pem)"
supabase functions deploy issue-activation
```

3. Выполнить `migration_040_materials.sql` в Supabase → SQL Editor.
4. Если деплой функции ругается на JWT — `supabase functions deploy issue-activation --no-verify-jwt`
   (безопасно: функция сама проверяет пользователя через `auth.getUser()` и `can_use_materials()`).

## Встраивание в программу (уже сделано для версии 1.3)

- `Program.cs`: в начале `Main` вызывается `ActivationGate.Ensure(...)`. Без активации не запускается окно программы и режимы,
  работающие с AutoCAD; офлайн-самотесты (`--self-test`, `--printer-self-test`, `--format-self-test`) проходят без ключа.
- `Build.ps1` подключает `activation-client\LayerPrintActivation.cs` и `ActivationForm.cs` (папка `activation-client` должна лежать
  рядом с папкой программы, как и `SPDS_PDF\lib`).
- Публичный ключ уже подставлен в `LayerPrintActivation.cs` (приватный — `activation-private.pem`, он создан локально).
- Готовая сборка: `Печать-по-слоям-1.3/Печать-по-слоям-1.3-активация.zip` — её и грузить во вкладку «Материалы».
  Если пересобираете сами, используйте `Build.ps1` из своей среды (с `SPDS_PDF\lib`).

## Выкладка новой версии

Собрать программу (проверка активации подключена в `Build.ps1`) → упаковать в ZIP вместе с `Инструкция.txt` и
`ThirdPartyNotices.txt` (его нужно сохранять при распространении) → «Материалы → Загрузить новую версию».
Старые `LayerPrint-1.x.exe` в папке программы проверки активации не содержат — **их раздавать нельзя**, только сборку из `…-активация.zip`.

## Ограничения (честно)

- .NET-программу можно декомпилировать и убрать проверку. Активация защищает от случайного/обычного
  распространения, но не от целенаправленного взлома.
- Бессрочный ключ нельзя отозвать: удаление активации освобождает место, но выданный ключ на старом компьютере
  продолжит работать. Если человек уволился — он потеряет доступ к скачиванию новых версий (его уберут из списка),
  но уже установленная копия останется рабочей.
- Смена пары ключей делает все выданные ключи недействительными — генератор не перезаписывает существующий ключ.
